# 四种指定表情图的五分类 CNN 训练记录

本目录完成标签整理、本地监督训练、浮点推理和 int8 权重导出。它是训练成果包，尚未替换 FPGA 中原来的二分类逻辑，不能直接烧录。六帧回放工程和已经生成的 BIT、HEX 仍使用原模型。

## 标签与图片

| ID | 名称 | 图片特征 |
| --- | --- | --- |
| 0 | 其他或无效画面 | 背景、局部脸部、头发服饰、线条图案和空白等 |
| 1 | 露齿笑 | 闭眼、嘴内有竖向牙齿线 |
| 2 | 闭眼微笑 | 闭眼、小幅弯曲的嘴 |
| 3 | 哭泣 | 有泪痕、张嘴 |
| 4 | 睁眼张嘴 | 护目镜人物、睁眼、张嘴 |

标签依据原图可见特征确定。闭眼微笑不能仅凭图片确定为无语，不使用该情绪名称。带红圈的图片是同一原图的标注版本，不进入训练。对应文件、裁剪坐标和原图 SHA-256 见 labels.json；预览见 previews/label_and_samples.png。

任务范围是区分这四张指定图案，不是识别任意角色的情绪。每个正类别只有一张独立原图。训练样本来自原图的轻度旋转、缩放、位移、亮度及少量噪声变化，未使用生成式模型修改人物五官，也没有额外制造新的表情类别。

## 数据与划分

训练集 640 张，每类 128 张；合成验证集 160 张，每类 32 张；较大变化合成测试集 160 张，每类 32 张。数据以 NPZ 保存，只另存一张样本预览，不生成大量松散图片。

三组数据使用不同随机种子，960 个归一化输入没有完全重复，但正样本仍来自相同的四张原图。这是同源开发实验，不能视为按独立拍摄批次划分的真实测试。原图数量不会因增强而增加。

负样本包括原图中的头发、配饰、衣服，不完整的眼部或嘴部区域，以及用户实拍照片顶部的房间背景。红色边缘叠加、字幕与红圈标注未作为表情正样本输入。

另保留 9 张已有的手机拍摄平板照片裁剪图，仅在训练、模型选择及量化标定完成后进行诊断。它们经过人工裁剪/校正，与训练原图内容同源，也没有背景负样本，不能代替 FPGA 摄像头原始帧测试。

## 网络与训练结果

输入是手动对齐的 2:1 面部区域，缩放为 32×32 灰度图，再按整数 min-max 归一化。动态范围不足 16 时输出全零输入。网络沿用原来的 1→4→8→8 通道卷积结构，前两层带最大池化，最后进行全局平均和 8→5 全连接。参数总数 965，比原二分类增加 27。

固定随机种子 20261031，CPU 训练 160 轮，按合成验证损失选择第 159 轮模型。浮点推理使用验证集选出的拒绝阈值：最大 softmax 分数至少 0.7，前两类分数差至少 0.2，否则输出类别 0。softmax 分数不是经过校准的实际正确概率。

| 数据 | 浮点模型含拒绝规则的正确数量 | 正确率 |
| --- | --- | --- |
| 训练集 | 628 / 640 | 98.1% |
| 同源轻度变化验证集 | 155 / 160 | 96.9% |
| 同源较大变化测试集 | 111 / 160 | 69.4% |
| 手机照片裁剪诊断 | 8 / 9 | 88.9% |

变化较大时主要出现哭泣与闭眼微笑混淆，以及应识别图案被拒绝。第 4 张手机照片裁剪图被模型直接判为无效画面，未将其计为正确。完整预测与混淆矩阵保存在 training_report.json；矩阵行是真实类别，列是预测类别。

## int8 导出与资源边界

weights_int8.hex 保存 940 个有效有符号 int8 权重，补齐至 1024 字节；quantization.json 保存 25 个 int32 偏置、层间移位和激活尺度。标定仅使用训练集。原卷积通道和两块 1024 字节激活缓冲的尺寸没有扩大。

int8 仅使用最大分数分类时，验证集 150/160、较大变化测试集 117/160、手机照片诊断 8/9。int8 与浮点的最大分类输出在验证集有 157/160 一致、测试集有 149/160 一致。浮点表格包含拒绝规则，两者不能直接用来判断量化提升或下降。

这些是 Python 整数算术检查，不是 FPGA RTL 验证。不能直接用此文件覆盖旧 weights.hex：旧 RTL 的全连接遍历、结果端口、类别判定和字幕仍按二分类实现。浮点拒绝阈值也不能直接用于整数分数。五分类 RTL 接入、整数拒绝规则、整机资源与时序和板级验证尚未完成。

现有六帧工程的片上 RAM 余量是 7 块；本训练没有重新综合。940 字节权重可容纳在原 1024 深度 ROM 中是容量计算，不能视为新整机已经满足资源约束。

## 本地使用

环境依赖见 requirements.txt。已有模型测试一幅手动裁剪的面部图：

```powershell
python -X utf8 predict.py photo_diagnostics/01_tablet_face.png
```

传入完整原图时必须给出面部裁剪坐标。例如：

```powershell
python -X utf8 predict.py sources/微信图片_202610281715_1.jpg --box 230 690 1030 1090
```

复核数据、模型保存和整数算术：

```powershell
python -X utf8 verify.py
```

在新的输出目录重现训练，保留本目录已完成结果：

```powershell
python -X utf8 train.py --output-dir ../reproduced_run
```

本包包含重现所需四张原图、背景裁剪和九张诊断裁剪图。无需从微信目录重新读取文件。verify.py 还用独立 NumPy int64 卷积核对了 10 个样本的各层整数输出，与 PyTorch 整数参考计算一致。真实 FPGA 摄像头原始帧测试数量仍为 0。
