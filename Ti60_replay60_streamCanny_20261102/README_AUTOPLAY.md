# 冻结后自动慢放（2026-11-01）

模式 3 在锁定最近六个完整 DDR 帧后，从最早一帧播放到最新一帧（编号 5→4→3→2→1→0），播放一次后停住。进入模式 3 或长按 SW3 重新采集后，都会自动播放。

- 播放期间显示彩色视频，Canny 工作面保持复位，不叠加上一幅图像的边缘。
- 播完停在最新帧，再计算这幅图像的 Canny 并显示红色边缘。
- SW1 选择更早一帧，SW2 选择更新一帧，六帧循环。有效的手动切帧会停止自动播放，并为所选图像重新生成边缘。
- DDR 选择尚未确认时，按键继续沿用原有的忽略规则，防止覆盖未完成的请求。
- SW3 长按解除锁定，等待八个显示帧后重新请求锁定，再从最早帧播放。最新集合可能包含旧帧，取决于采集帧率。
- SW3 短按离开模式 3；模式 0、1 的冻结、模式 2 的快照与左右延时对比沿用原逻辑。

顶层 `u_camera_sobel` 启用 `AUTO_REPLAY=1`、`PLAY_FRAMES=6`。每次选择得到同步后的 DDR 确认，再计满六个显示帧后请求下一帧；确认等待额外占时，所以实际切换速度略低于 60 Hz 输出下的 10 帧/秒。切换仅在显示帧起点请求，DDR 仍在读描述符边界应用选择，原有预取排空机制保留。最后一帧等待结束才释放 Canny 复位。

修改只增加控制寄存器，复用原六帧 DDR 存储，不扩大图像缓存。六帧代表的原始时长取决于实际采集和完整提交速率，不是几秒钟的视频录像。

验证入口：`python -X utf8 tests/run_replay6_tests.py`。新增控制测试覆盖完整播放顺序、确认超时等待、播放期间禁用边缘、最终停住、手动打断、长按刷新、退出重入及模式 2 隔离；视频集成测试增加 `AUTO=1` 配置，沿用三帧预取模型核对 RGB、同步和同帧边缘。

本版本构建输出使用独立目录 `outflow_autoplay`，避免与原 `outflow_cnn` 烧录文件及哈希记录混淆。原 `program_cnn.ps1` 仍指向旧目录，不能用它下载本版本。新文件需在 Efinity Programmer 中选择；工程修改和仿真不代表已完成开发板实测。
