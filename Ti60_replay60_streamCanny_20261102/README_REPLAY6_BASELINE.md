# Ti60 CNN + DDR3 六帧冻帧回放工程

2026-11-01 更新：当前顶层已启用模式 3 自动慢放，操作与验证说明见 [README_AUTOPLAY.md](README_AUTOPLAY.md)。下文保留手动回放基线记录。

器件：Ti60F225，I3。工程入口：`ti60f225_oob.xml`。构建工具：Efinity 2026.1.132。

本版本在已有可编译 CNN 完整工程上增量修改，复用 DDR3 控制器、AXI 读写模块、摄像头采集、ISP、Canny、HDMI 和按键处理。基础工程保留在原目录，交付副本不修改摄像头寄存器表、引脚约束和时钟约束。本次没有烧写开发板；仿真和编译结果不能替代摄像头、显示器及断电启动的实物验证。

## 按键操作

| 操作 | 功能 |
| --- | --- |
| SW3 短按并松开 | 模式 0 → 1 → 2 → 3 → 0 |
| 模式 0 | 保留原灰度、边缘对照显示 |
| 模式 1 | 保留彩色、红色边缘和原 CNN 识别显示 |
| 模式 2 | 保留单帧快照，冻结后生成同帧 Canny 叠加 |
| 模式 3 | 冻结最近六个已完整写入 DDR 的图像，默认显示其中最新一帧 |
| 模式 3，SW1 短按 | 上一帧，即更早的一帧，六帧循环 |
| 模式 3，SW2 短按 | 下一帧，即更新的一帧，六帧循环 |
| 模式 0、1、2，SW1 / SW2 | 保留阈值增加 / 减少 8 |
| SW3 按住约 1 秒 | 模式 0、1 冻结或恢复；模式 2、3 解除锁定一段时间后重新冻结 |
| SW0 | 沿用原工程复位 |

六帧按内部序号 0～5 排列，0 为最新，5 为最早。SW1 的顺序是 0→1→2→3→4→5→0；SW2 相反。内部序号没有增加到屏幕文字中。按键选择等待 DDR 帧边界确认；尚未确认时的连续按键被忽略，防止跨时钟域未完成的选择被覆盖。

多帧对比采用手动逐帧对比：六幅冻结图像保持不变，在相同阈值下切换并重新计算边缘。此版本不做六宫格或并排显示，也不自动播放视频。回放期间 SW1、SW2 不改变阈值。进入回放时不足六个完整帧，会继续采集到六帧后锁定。上电过早请求单帧冻结时，等待第一幅有效图像后再确认冻结，避免锁住未初始化的 DDR。长按刷新保留原机制，解除冻结八个显示帧后再次请求冻结；若摄像头帧率较低，新集合可能包含上次冻结后的新帧和较早的帧。

## 存储与通路

摄像头 RAW 数据 → 原打包/FIFO → 原 DDR3 AXI 写入 → 十个外部 DDR 槽位管理 → 原 DDR AXI 读取/FIFO → ISP → Canny / CNN / 原有模式 → HDMI。

每幅图像为 1920×1080，RAW 数据按每像素 16 bit 存储，完整图像为 4,147,200 字节。输入总线一次携带两个像素，故帧缓冲上层参数沿用 960×1080、32 bit。槽位步长为 4,147,712 字节，包含原有 512 字节间隔。十个槽位共预留 41,477,120 字节，约 39.56 MiB。DDR 配置文件的 3 位 bank、14 位 row、10 位 column、16 位数据总线对应 256 MiB 地址容量。

对用户提供六个历史帧，额外槽位用于保护当前正在显示、预取或写入的图像。六帧图像全部存于外部 DDR，片上只增加帧号、锁定状态和握手寄存器；不增加六帧的片上图像缓存。布局布线后的资源和时序以 `outflow_cnn/cnn_verification.json` 为准。

## 完整帧与画面一致性

1. 上电等待摄像头帧检测稳定且实测长度等于配置的完整图像长度；零长度帧不会启动写入。写入起点只在摄像头帧边界接受。槽位在该帧所有写响应返回之前保持独占。
2. 复用已有 `frame_write_commit`，以 AXI B 响应确认整帧提交，不把原先提前发出的换银行信号当作写完成。
3. 最近六帧队列只接收完整提交的帧。正在写入、正在读取、等待下一帧读取和冻结的历史槽位均不得被重新分配。
4. 进入回放时等待当前写入帧提交，再复制六帧槽位列表并停止新写入。冻结后六幅图像内容不变。
5. 选择信号经过同步与稳定性检查，仅在读帧描述符边界更新。新选择收到确认后，显示处理等待四个显示帧排空既有预取，再重算 Canny，防止旧边缘图叠加到新图像。
6. 如果上一幅图像仍有未发送的写数据，新摄像头帧就到达并重置采集 FIFO，写侧将置故障，停止发布后续图像，保护最后已提交画面；复位后重新初始化。延迟仅发生在 B 响应、图像数据已经发完时，新采集帧会被跳过，等待原帧提交后恢复。

以上保护针对完整帧归属和正常视频时序下的切换。实物上仍应检查 DDR 校准、连续显示、进入/退出回放和快速按键；任意长总线停顿或摄像头链路错误不能仅凭 RTL 仿真保证显示正常。

## 修改范围

- 新增 `rtl/replay6_slots.v`，管理最近六帧和十个外部槽位。
- 扩展 `frame_buffer.v` / `ddr_buffer.v` 的帧选择位宽，补齐上层帧尺寸、帧数参数到底层的传递。
- `ddr_wr_buffer.v` 增加可选帧开始保护、最后一个数据突发结束后停止和故障屏蔽；旧配置默认关闭新保护，保留原有测试入口。
- 修正采集帧长度检测的复位赋值与稳定性比较；将 DDR 读写地址、长度寄存器的异步复位值固定为零，帧开始时再加载实际参数，消除综合后的直接组合反馈。空帧不会占用写槽位。
- DDR 读写地址增量改为显式 9 位长度运算，避免未定宽常量的仿真歧义。
- 将 `canny_snapshot_control.v` 和 `sc431_sobel_video.v` 参数化，扩展六帧双向切换，同时保留默认双帧配置供历史回归。
- 顶层启用六帧配置；CNN 权重、CNN RTL、Canny 算法、ISP、摄像头设置和物理约束保持原样。

CNN 继续使用原来的 938 参数 int8 二分类网络，只判断固定取景框中的护目镜人物图案与其他画面，不代表四类表情识别。本次未重新训练模型。

## 仿真和构建

完整复现：

```powershell
powershell -ExecutionPolicy Bypass -File .\build_cnn.ps1 -PythonExe "你的 Python 路径"
```

仅运行新增验证：

```powershell
python -X utf8 tests/run_replay6_tests.py --full
```

新增六组测试包括：上电空帧拒绝及真实采集打包通路；六帧历史和槽位保护；按键双向循环及确认；实际 DDR 读写 RTL 与行为 AXI 存储器联合测试；六帧与 Canny/HDMI 显示同步联合测试；1920×1080 RAW16 六个完整帧的存取核对。原有 20 组回归和 3 组 CNN 测试一并执行。行为存储器代替物理 DDR 芯片和 FIFO 原语，不能验证板上信号完整性和 DDR PHY 校准。

`test_output` 保存仿真日志；`outflow_cnn` 保存综合、布局布线、时序报告和烧录文件。`DELIVERY_MANIFEST.json` 记录修改文件与交付文件哈希。构建脚本仅生成文件，不连接开发板。
